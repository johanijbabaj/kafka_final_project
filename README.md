# kafka_final_project

## Overview

This project implements an analytical platform for a marketplace, processing data from shops and clients using Apache Kafka and related technologies.

## Preparation

Run the following command to start the Docker containers:

```bash
python -m venv venv
```
```bash
source venv/bin/activate
```
```bash
pip install -r requirements.txt
```
```bash
docker compose up --build -d
```

<b><u> Please be aware that Elasticsearch might take a considerable amount of time to start up.</u></b>

After the containers are running, execute the following scripts in order:

1.  Add ban rules for product filtering: `script_ban_rules.script`
2.  Register the Mirror Connector to replicate Kafka data: `script_mirror.script`
3.  Register the Elasticsearch Connector to index product data: `script_elastisearch.script`
4.  Generate initial product data to simulate shop interactions: 
`script_products_generation.script`
5.  Explore the client API (FastAPI) methods using Swagger at [http://localhost:8001/docs#](http://localhost:8001/docs#):
      * `/search_product`: Allows clients to search for products (backed by Elasticsearch).
      <b>PLEASE use it to </b>
      * `/recommendations`: Provides personalized recommendations (generated by Spark)
      <b>Copy client_id form the method `/search_product` and execute request to get recommendations.</b>

## Component Breakdown and Task Mapping

**Data Ingestion (Step 1):**

  * **Kafka Cluster (kafka-0,1,2):** The central message bus. Shop data (simulated by `script_products_generation.script`) and client requests are ingested here.
  * **SHOP API (Emulated):** `script_products_generation.script` simulates shops sending product information in JSON format to Kafka topics.
  * **CLIENT API (Emulated by FastAPI):**
      * `/search_product`: Handles client search queries, likely by querying Elasticsearch. These queries are also intended for Kafka for analytics.
      * `/recommendations`: Provides recommendations based on data processed by Spark. Client requests for recommendations are also intended for Kafka analytics.
      NOTE: if you don't get recomendations please check in docker `spark-app-client-recommendations` container. 

**Kafka Infrastructure (Step 2):**

  * **Kafka Cluster (kafka-0,1,2):** The core Kafka brokers, configured for:
      * Topic creation (configured via `KAFKA_CFG_AUTO_CREATE_TOPICS_ENABLE: true`).
      * Replication for fault tolerance (configured by default Kafka settings).
  * **Mirror Kafka Cluster (kafka-mirror-0,1,2):** A secondary Kafka cluster for data duplication and to serve analytical workloads, ensuring resilience. Data is mirrored from the main cluster using the **Mirror Connector**.

**Analytical System (Step 3):**

  * **Mirror Kafka Cluster (kafka-mirror-0,1,2):** Serves as the data source for the analytical system.
  * **Spark Applications:**
      * **spark-app-kafka-to-hdfs:** Reads product and client request data from the mirror Kafka cluster and persists it in **HDFS** for batch analytics.
      * **spark-app-client-recommendations:** Reads relevant data from the mirror Kafka cluster, performs analytical processing (simulated recommendation logic), and likely makes these recommendations available to the **FastAPI** service.
  * **HDFS (namenode, datanode):** Hadoop Distributed File System, used by Spark for storing and processing large datasets.

**Stream Processing (Step 4):**

  * **Kafka Cluster (kafka-0,1,2):** Receives product data from the emulated **SHOP API**.
  * **Faust Application (faust-app):** Implements stream processing to check if incoming product data matches a list of banned products (managed externally - *CLI interface not explicitly implemented in this setup*). Filtered (non-banned) products are then processed further.

**Database (Step 5):**

  * **Elasticsearch:** Used as the primary data store for product information, enabling efficient searching via the **FastAPI** `/search_product` endpoint. The **Elasticsearch Connector** reads processed (non-banned) product data from a Kafka topic and indexes it into Elasticsearch.

**Monitoring (Step 6):**

  * **ui (Kafka UI):** Provides a web interface for monitoring and managing the Kafka clusters.
  * **prometheus:** Collects metrics from various components (Kafka brokers via **jmx-kafka** exporters, potentially Spark, etc.).
  * **grafana:** Visualizes the metrics collected by Prometheus, providing dashboards for monitoring system health and performance.
  * **alertmanager:** Configured to send alerts based on Prometheus rules (e.g., broker down).
  * **jmx-kafka-0/1/2:** JMX exporters that expose Kafka broker metrics in a format Prometheus can understand.

**Hadoop & Spark Infrastructure:**

  * **HDFS (namenode, datanode):** Provides distributed storage for batch processing by Spark.
  * **Spark Cluster (spark-master, spark-worker):** The distributed processing engine used for analytical tasks like data transformation and generating recommendations.

**Client Interaction:**

  * **FastAPI (Client API):** The interface for clients to interact with the platform, providing endpoints for searching products and retrieving recommendations.
  * **Swagger UI (http://localhost:8001/docs#):** A user-friendly interface for exploring and testing the FastAPI endpoints.
